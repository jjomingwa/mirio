# 구현 플랜

이 디렉터리는 저장소의 중간 규모 이상 구현 작업을 계획하고 추적하기 위한 문서를
보관한다. 플랜은 제품 요구사항을 대신하지 않으며, 확인된 사용자 요청과 현재
코드베이스 조사 결과를 실행 가능한 순서로 연결한다.

## 운영 원칙

- 플랜은 전체 저장소 기준의 순번으로 관리한다.
- 파일명은 `PLAN-NNN-slug.md` 형식을 사용한다.
- 새 번호는 인덱스와 기존 플랜 파일에서 확인한 가장 큰 번호의 다음 번호를
  사용한다.
- 기존 번호는 삭제, 완료, 취소 또는 보관 여부와 관계없이 재사용하거나 재배정하지
  않는다.
- 독립적인 구현, 브랜치 또는 검증 단위는 각각 새 번호를 사용하며, 세부 단계는 한
  플랜 안에서 관리한다.
- 각 플랜은 현재 코드베이스 조사 결과와 확인되지 않은 사항을 구분해 포함한다.
- 플랜은 구현 중에도 진행 상황, 결정, 실제 변경 파일과 테스트 결과에 맞춰
  갱신한다.
- 코드 작성 완료와 요구사항 검증 완료를 구분한다.
- 번호 플랜은 작업을 자동으로 활성화하지 않는다. 자율 게임 작업은
  `.goal/backlog.json`과 Goal Harness의 상태 및 선택 규칙을 따른다.

## 상태

- `Draft`: 초안이거나 구현에 필요한 정보가 부족함
- `Ready`: 구현 가능한 수준으로 검토 완료
- `In Progress`: 구현 진행 중
- `Blocked`: 외부 조건이나 미해결 문제로 중단
- `Implemented`: 코드 작성 완료
- `Verified`: 테스트와 완료 조건 검증 완료
- `Cancelled`: 구현 취소
- `Superseded`: 다른 플랜으로 대체됨

## 새 플랜 작성 절차

1. 이 인덱스와 `PLAN-*.md` 파일에서 가장 큰 번호를 확인한다.
2. 다음 번호와 짧은 kebab-case slug로 파일명을 정한다.
3. [`templates/implementation-plan-template.md`](templates/implementation-plan-template.md)를
   기준으로 요청과 관련 코드베이스를 조사해 작성한다.
4. 구현 전에 완료 조건, 수정 예상 파일, 의존 관계, 위험과 검증 방법을 검토한다.
5. 아래 목록에 플랜을 추가한다.

번호가 한 번 부여된 플랜은 삭제하는 대신 필요하면
[`archive/`](archive/README.md)로 옮기고 상태와 이동 경로를 인덱스에 유지한다.
